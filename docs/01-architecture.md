# Architecture

## 1. Repository layout

```
vulkan-engine/
├── CMakeLists.txt          top level: dependencies + the three targets below
├── cmake/                  CMake helpers: Dependencies, Shaders (ve_compile_shaders), Game (ve_setup_game)
├── docs/                   this planning folder
├── engine/                 ve_engine   – static library, the core engine (namespace ve)
│   ├── src/ve/app/         Engine.cpp: the composition root (creates + wires every module, main loop)
│   ├── src/ve/core/        Engine.hpp (service locator), Window, Input, Time, Log, Jobs
│   ├── src/ve/gfx/         Thin Vulkan layer ("RHI"): Device, Swapchain, Buffer, Image,
│   │                       Bindless descriptors, Pipelines, Samplers
│   ├── src/ve/render/      Renderer, RenderGraph, RenderPass, Material, Shader, Mesh,
│   │   └── passes/         built-in passes: Shadow, Opaque, Transparent, Composite, UI
│   ├── src/ve/scene/       Scene, GameObject, Component, Transform, Camera, MeshRenderer, Lights
│   ├── src/ve/physics/     Jolt-backed physics: PhysicsWorld, Collider, Rigidbody, CharacterController
│   ├── src/ve/assets/      AssetManager, texture loading (stb), glTF loading (cgltf), Model
│   ├── src/ve/audio/       AudioSystem, AudioClip, AudioSource, zones (miniaudio); Music, Ambience
│   ├── src/ve/nav/         Navmesh building (Recast), paths + agents (Detour)
│   ├── src/ve/ui/          ImGui integration + engine debug overlay
│   ├── src/ve/world/       Terrain, FoliageSystem (streamed scattering), GrassPass (GPU grass), Vegetation (scene types), LodModel
│   └── shaders/            engine shaders + include/ve.glsl (the shared shader interface)
├── effects/                ve_effects  – OPTIONAL static library (namespace vfx)
│   ├── src/vfx/            Atmosphere (sky + volumetric clouds), VolumetricFog, Bloom,
│   │                       Particles (component + pass), Weather,
│   │                       ScreenSpaceGI, ScreenSpaceReflections, DepthOfField (opt-in)
│   └── shaders/
├── templates/game/         starter project for a game that lives outside this repo
├── sandbox/                savanna     – the test game executable
│   ├── src/                game objects: player, day/night, terrain, vegetation, campfire...
│   ├── shaders/            game-specific shaders (terrain, grass, water)
│   └── assets/             generated by tools/generate_assets.py (textures, glTF, audio)
└── tools/                  asset generation scripts
```

Build outputs go to `build/bin/`, with compiled shaders in `build/bin/shaders/`
and assets copied to `build/bin/assets/`.

**Two ways to build.** (1) Configure this repo directly, which builds the engine
plus the sandbox (engine development). (2) A game's own CMakeLists calls
`add_subdirectory(<engine> vulkan-engine)` and then `ve_setup_game(<target> ASSETS ... SHADERS ...)`.
`VE_BUILD_SANDBOX` defaults to off in that case, and all outputs go to the
*game's* `build/bin`. `templates/game` is a working example, and the sandbox
itself uses `ve_setup_game`.

**Dependencies**
- System: Vulkan SDK/headers (1.3), SDL2, glm, `glslc`.
- Fetched by CMake (pinned): Vulkan Memory Allocator, Dear ImGui, cgltf,
  stb_image, miniaudio, Jolt Physics 5.2.0 (built with its own CMake, SSE4.2, private to `ve_engine`).

## 2. Module dependency rules

```
sandbox ──► ve_effects ──► ve_engine
   └──────────────────────► ve_engine
```

- `ve_engine` never includes anything from `effects/` or `sandbox/`.
- `ve_effects` only uses public engine APIs, the same ones a game would use.
  This keeps us honest: if an effect needs an engine change, that change must
  be a *generic* extension point.
- Inside the engine: `core` ← `gfx` ← `render` ← `scene`. `assets`, `audio` and
  `ui` sit on top. `scene` components (MeshRenderer, Light, Camera) are plain
  data that the renderer *reads*. The renderer does not own scene objects.
- **Inside the engine** the modules are layered, and lower modules expose
  extension points instead of including the ones above them (D23):
  core ← gfx ← render ← scene; physics, anim, gameplay and net build on
  scene; world and nav on those; assets, audio, ui and debug on top; the
  editor may use everything; `app/Engine.cpp` sits above it all. It is the
  composition root, the only place that creates the modules and wires them
  together. `core/Engine.hpp` is the service locator every module may include
  (`Engine::get().renderer()`...): it only forward-declares the subsystems,
  so including it doesn't pull higher modules in. Lower modules offer
  extension points that the root connects: each module's
  `registerXTypes(TypeRegistry&)`, `SkinningSystem::addGatherer`, render's
  `DebugLineBuffer`, `Engine::atShutdown`, `Engine::editorPaused`,
  `registerModelMarker` (gameplay and world turn marker nodes of imported
  models into their components). `tools/check_layering.py`
  holds the allowed-dependency table and the few known exceptions (each with
  its reason) and fails on anything else; run it after changing includes.
- **Threads:** one engine job pool (`ve/core/Jobs.hpp`, D24): hardware threads
  − 1 workers (max 15). Foliage, terrain LOD, grass bakes, navmesh tiles and
  shader compiles submit jobs instead of owning threads. Jobs own their
  inputs and results (`shared_ptr`), so owners cancel and drop them without
  waiting; workers never touch the scene, renderer, device, physics world,
  audio or ImGui. Jolt keeps its own small pool (`jobs::physicsThreadCount()`),
  which only runs during a physics step.

## 3. The frame

`Engine::run()` drives everything:

```
loop:
  Time::tick()                       real dt, clamped (max 0.25s)
  Input::beginFrame(); poll SDL events → Window / Input / ImGui
  UiLayer::beginFrame()              ImGui::NewFrame
  Scene::startPending()              start() on objects/components spawned since last frame
  while accumulator >= fixedDt:      fixed timestep (default 50 Hz, max 5 steps/frame)
      Scene::fixedUpdate(fixedDt)      gameplay forces, CharacterController::move()
      PhysicsWorld::step(fixedDt)      kinematic bodies follow Transforms, Jolt update, record poses
  PhysicsWorld::interpolate(alpha)   dynamic bodies/characters -> Transform, between last two steps
  Scene::update(dt)
  Scene::lateUpdate(dt)              cameras/followers go here
  Scene::onGui(); UiLayer::drawDebugOverlay()
  AudioSystem::update(listener = main camera)
  Renderer::render(scene)            see §5
  Scene::flushDestroyed()            deferred destruction
```

**Loading screens** (`Engine::beginLoading(loadingScene)`): until loading
ends, a frame instead runs one queued load step (`addLoadStep`, main-thread
work such as loading the scene file), updates the world like the editor's
Edit mode (only `runInEditor` objects: terrain, foliage and grass keep
streaming; no fixed steps / physics, gameplay waits), polls the load tasks
(`addLoadTask`, progress 0..1 of work spread over frames, e.g. foliage
filling its cells on the job pool) and updates + draws the loading scene,
a small scene of the game's (usually one object drawing UI in `onGui`).
Those frames draw only the passes with `RenderPass::runsWhileLoading`
(instance uploads, skinning, the UI over a cleared screen). Loading ends
when every step ran and every task reports 1 (and `minSeconds` passed); the
loading scene is destroyed and the next frame is the world's.
`VE_CAPTURE_FRAME` / benchmarks count world frames only.

What a loading screen waits for is "ready to play here", not the whole
world: foliage counts only the cells within `FoliageSettings::readyDistance`
(300 m) of the viewer (big trees drawn kilometres away keep streaming in,
nearest first, after play starts), and the terrain's first LOD view is
built on the job pool with no per-frame upload budget while loading
(Savanna: about 0.9 s to play in Release, was 2.4 s).

**In the editor** (Edit mode, or a game started in it): `beginLoading`
shows no loading scene. Frames stay normal editor frames (the world paused,
drawn as it fills in), one load step runs per frame, and the editor draws a
progress panel from `loadStatus()` / `loadProgress()`; loading ends as soon
as steps and tasks are done, and Play waits until then. `Editor::openScene`
goes through the same path, so opening a large scene shows its terrain,
vegetation and navmesh progress.

## 4. Scene model (Unity-style)

- **`GameObject`** has a name, a `Transform` (position / rotation quat / scale,
  parent/children, cached world matrix), an active flag, and a list of
  components. It is *subclassable*: override the lifecycle hooks to write
  behaviour (`class Player : public ve::GameObject`).
- **`Component`** is the same set of hooks (both derive from `ve::Behaviour`,
  which declares them once), attached with
  `go.addComponent<T>(args...)`. Engine components:
  `Camera`, `MeshRenderer`, `DirectionalLight`, `PointLight`, `AudioSource`
  (plus `vfx::ParticleEmitter` in effects).
- **`Scene`** owns objects (`std::unique_ptr`). It provides
  `spawn<T>(args...)`, `find(name)`, and `forEach<T>()`, a typed registry
  so the renderer can iterate e.g. all `MeshRenderer`s without scanning every
  object. Components are bucketed by their exact type; a query for `T` caches
  the list of buckets whose type is `T` or derives from it, and rebuilds it only
  when a new component type appears.
- **Hooks cost nothing unless overridden.** The base `update`, `fixedUpdate`,
  `lateUpdate` and `onGui` set a "not overridden" bit the first time they run.
  The Scene then skips them, and skips objects with no such hook on themselves
  or any component without walking their hierarchy (model
  nodes, static props).
- Spawning during an update is safe: new objects get `start()` at the start of the next frame.
  `destroy()` is deferred to end of frame and also destroys children.
  `removeComponent()` takes the component out of `components()` and the
  registry at once (its `onDestroy()` runs then, if it started) but the scene
  frees it at the end of the frame, so a hook may remove itself or a sibling.
  Bucket order is not stable (removal swaps the last item into the gap).
- **Handles, not pointers, across frames** (`ve/scene/ObjectRef.hpp`, D22).
  Every GameObject has a random 64-bit `id()`; `scene.findById(id)` is O(1)
  and returns null once the object is destroyed. `ObjectRef<T>` stores just
  the id and resolves it on each `get(scene)` (with a checked cast), so it
  can't dangle when the editor deletes or replaces objects. `ComponentRef<T>`
  does the same for components: owner id + address + `Component::serial()`
  (never reused), checked against the owner's live components before the
  address is trusted. Members that outlive a frame use these, never a raw
  `GameObject*` / `Component*` (components an object adds to itself and
  that die with it are the exception). `scene.findFirst<T>()` finds the
  first object of a class (e.g. the scene's `vfx::Weather`).
- Global access: `ve::Engine::get()` and helper accessors on GameObject
  (`input()`, `time()`, `assets()`, `audio()`, `renderer()`, `scene()`).

## 5. Rendering

### 5.1 GPU data model: one interface for every shader

Every pipeline uses **one global pipeline layout**:

| Set/binding | Contents | Notes |
|---|---|---|
| set 0, b0 | `FrameGlobals` UBO | view/proj (+inverses, unjittered prev), camera pos, screen size, time, ambient, light counts, 8 user `globalParams` vec4s, builtin texture indices, camera jitter |
| set 0, b1 | `LightBuffer` SSBO | directional lights (with cascade matrices/splits), point lights, shadow view matrices, light clusters |
| set 0, b2 | `MaterialBuffer` SSBO | `MaterialData[]`: 12 × vec4 params + 16 uint texture indices = 256 B each |
| set 0, b3 | `sampler2DArrayShadow` | directional shadow cascades (all lights × cascades as layers) |
| set 0, b4 | `samplerCubeArrayShadow` | point light shadow cubes |
| set 0, b5–b9 | instancing SSBOs | instances, visible-instance lists, indirect draw commands, instance groups, cull views (see §5.7) |
| set 0, b10–b13 | skinning SSBOs | rest vertices, joint weights, this frame's joint matrices, skinned output (see §5.7b) |
| set 0, b14 | `DecalBuffer` SSBO | this frame's decals (≤ 1024, sorted) and their clusters (see "Decals" below) |
| set 1, b0 | `image2D storageImages[]` | bindless storage images (compute) |
| set 1, b1 | `sampler2D textures[]` (+ `sampler3D`/`samplerCube` aliases) | **bindless textures**, 4096 slots |
| push constants | 128 bytes, all stages | default draw layout: `mat4 model; uint material; uint viewIndex; uint lightIndex; uint flags; vec4 custom;` Passes may use their own struct |

**Clustered point lights.** The camera frustum is split into 16 × 9 screen
tiles × 24 logarithmic depth slices. Every frame the renderer bins the point
lights (≤ 256, already frustum culled and sorted on the CPU) into the clusters
their bounding boxes touch: `LightBuffer::clusters` holds each cluster's
range in `clusterLights` (8-bit light indices). `veEvaluateLighting` (and any
shader using `veLightList(P)`) only visits the lights of the point's cluster;
off screen, or if the list overflows (`clusterParams.z == 0`), it falls back
to every light. Only the used part of the buffer is uploaded.

**Decals** (`render/Decals.hpp`, `scene/Decal.hpp`, `ve_decals.glsl`). A decal
is an oriented box that projects textures along its local -Z onto whatever
surface lies inside it (bullet holes, puddles, cracks). Placed ones are
`DecalProjector` components (the box is the object's transform); transient
ones go through `Renderer::decals()` (`DecalSystem`: a ring buffer, oldest
replaced, optional lifetime + fade-out, no GameObjects). Each frame
`SceneGatherer` culls them (frustum, `drawDistance`), keeps the nearest 1024,
sorts them by `sortOrder` (placed before spawned, then age) and writes
`DecalBuffer`; `LightClusterer` bins their view-space boxes into the light
cluster grid (16-bit indices). This is a forward renderer, so decals are not
a pass drawn over the lit image: material shaders call
`veApplyDecals(surface, geometricNormal, dPdx, dPdy, receiveLayers)` before
`veEvaluateLighting`, and each decal blends albedo (mix or multiply), normal
(a normal map on the decal's frame, built on the geometric normal; `flatten`
smooths the surface's own bumps), roughness and metallic, each with its own
opacity times the decal's alpha and fades (angle to the projection
direction, never on back faces; box depth; distance; lifetime). Lighting,
shadows and the thin G-buffer (SSR on puddles) all see the result.
`standard.frag` (receive mask in `params[3].w`, inverted) and `terrain.frag`
receive decals; custom shaders opt in with the same call.

**Temporal AA** (`RendererSettings::temporalAA`, off by default; Savanna turns
it on). The projection is jittered by an 8-position Halton (2, 3) sequence
(`frame.jitter`); `TemporalAAPass` (first PostProcess pass) reprojects last
frame's result with the camera motion from depth (closest of 3×3, unjittered
`prevViewProj`), samples it with Catmull-Rom, clips it to the current 3×3
YCoCg variance box and blends it in with weight `feedback` (0.9), on
tonemapped values. `prevViewProj` is the unjittered matrix for every temporal
effect.

**Motion vectors.** The renderer keeps every MeshRenderer's last world
matrix; opaque items whose matrix changed go to `FrameData::moving`.
`VelocityPass` (AfterOpaque, with TAA) draws just those into `Velocity`
(RG16F: last frame's unjittered UV minus this frame's) where they are the
visible surface (compared with SceneDepth), over a "not moving" clear value.
TAA uses that motion where present and camera motion from depth elsewhere,
so moving objects keep their history instead of ghosting. Vertex animation
(wind, and later skinning) isn't included yet.

Set 0 has one copy per frame in flight. Set 1 is a single update-after-bind
bindless set. Because every shader shares the layout, descriptor sets are bound
once per pass and any shader can read any texture by index. A material is just
an index into `MaterialBuffer`. A full-screen pass's inputs are just texture
indices in push constants.

`engine/shaders/include/ve.glsl` declares all of this. It also provides helpers
(`veTexture(idx, uv)`, `veMaterial()`, `veEvaluateLighting(...)`, shadow
sampling, depth reconstruction). C++ mirrors are in `ve/render/GpuTypes.hpp`
and must be kept in sync.

**Custom shadow casters:** implement `ve::ShadowCaster::drawShadow(ctx, view)`
and register it with `renderer.addShadowCaster(this)` to draw non-scene
geometry into the directional cascades. The depth target is already bound;
bind a `PassKind::ShadowDirectional` pipeline and push `viewIndex`.

**Directional shadow casters:** shadow pipelines use depth clamp, so the
cascade cull frustum has no near plane. Casters anywhere between the sun and
the cascade (e.g. distant mountains at sunset) are pancaked to depth 0 and
still shadow it.

**Depth convention:** the main camera uses **reversed-Z** (near → 1, far → 0,
compare `GREATER_OR_EQUAL`, clear to 0) for precision over long view
distances. Shadow maps use standard Z (clear to 1, `LESS_OR_EQUAL`).

### 5.2 Fixed vertex format

`ve::Vertex { vec3 position; vec3 normal; vec2 uv; vec4 tangent; vec4 color; }`
(64 bytes), with uint32 indices. A `Mesh` is one vertex buffer + one index
buffer in device-local memory, plus `Submesh` ranges (each with its own
material slot) and a local AABB.

### 5.3 Shaders & materials

- `ShaderDesc` names a vertex and fragment SPIR-V file and pipeline state:
  blend mode (opaque / alpha / additive / premultiplied), cull mode, depth
  test/write, render queue (Opaque 2000, AlphaTest 2450, Transparent 3000), shadow
  casting, and optional custom shadow vertex/fragment shaders (e.g. for wind sway).
- `Shader` lazily builds and caches pipelines for each *pass kind* (Forward,
  ShadowDirectional, ShadowPoint).
- `Material` = `shared_ptr<Shader>` + a `MaterialData` block (`setVector(slot)`,
  `setTexture(slot)`). The renderer assigns each material a slot in the
  MaterialBuffer and uploads all live materials each frame.
- **Forward pipelines have two colour targets:** SceneColor, plus SceneNormal
  (the thin G-buffer). Opaque/AlphaTest shaders write
  `layout(location = 1) out vec4 outGBuffer = veGBuffer(N, roughness)`.
  Transparent pipelines get write mask 0 on the second target, so they don't
  need the output. This uses `independentBlend`, which is a required device
  feature.
- `StandardMaterial` wraps the built-in PBR shader (`standard.vert/frag`):
  base colour, roughness, metallic, emissive, albedo/normal/MR/emissive textures,
  alpha cutoff, and vertex-colour multiplication.

### 5.4 Render graph

`RenderGraph` is an **ordered list of `RenderPass` objects with automatic
resource transitions**. It is deliberately simple. There is no pass culling,
no aliasing and no async compute.

- Resources are named textures. They are either **screen-relative**
  (`scale` × swapchain size, recreated on resize) or **fixed size**. They are
  created with `graph.createTexture(name, desc)` and looked up with
  `graph.texture(name)`. Each texture is registered in the bindless table
  (`sampledIndex`) so shaders can read it.
- Built-in resources: `SceneColor` (RGBA16F HDR), `SceneDepth` (D32F, reversed-Z),
  `SceneNormal` (RGBA16F thin G-buffer: xyz world normal, w roughness, 0 = nothing
  drawn; `frame.builtinTextures.z`), `DirShadowMap` (D32F 2D array), `PointShadowMap` (D32F cube array),
  `Backbuffer` (the swapchain image, imported each frame).
- A pass has a **stage** (`Shadow 100, Opaque 200, Sky 300, AfterOpaque 400,
  Transparent 500, PostProcess 600, Composite 700, Overlay 800`) plus an
  `order` within the stage. Passes run sorted by (stage, order).
- Each frame a pass **declares** what it touches
  (`b.write(tex, Access::ColorAttachment)`, `b.read(tex, Access::Sampled)`,
  `DepthAttachment`, `DepthRead`, `Storage`, `Transfer*`). The graph tracks the
  current layout/stage/access of every texture and inserts
  `vkCmdPipelineBarrier2` before the pass as needed.
- Pass hooks: `setup(graph)` (once: create textures/pipelines),
  `prepare(FrameData&)` (CPU, before GPU buffers are uploaded; can edit frame
  globals, e.g. ambient light or global params), `declare(builder)`,
  `execute(ctx)`, `onResize(graph)`, `onGui()` (debug UI).
- `FullscreenPass` is a helper base class. It builds a pipeline from a fragment
  shader plus the built-in full-screen-triangle vertex shader, so a
  post-process effect is about 30 lines of C++ plus a fragment shader.

Default pass list:

| Stage (order) | Pass | Module |
|---|---|---|
| Shadow (-100) | `InstanceCullPass` (upload changed instances, GPU culling → indirect commands) | engine |
| Shadow | `ShadowPass` (cascades + point cubes; instanced draws in cascades) | engine |
| Opaque | `OpaquePass` (clears, draws Opaque/AlphaTest queues) | engine |
| Opaque (10) | `GrassPass` *(per grass layer, added by the game)*: GPU-placed clumps per visible tile | engine (world) |
| Sky | `AtmospherePass` (sky LUT → half-res clouds → sky where depth == far) | effects |
| AfterOpaque (0) | `ScreenSpaceGIPass` *(opt-in)*: half-res bounce + AO → `scene * ao + bounce` | effects |
| AfterOpaque (10) | `ScreenSpaceReflectionsPass` *(opt-in)*: half-res trace → premultiplied blend | effects |
| Transparent (0) | `TransparentPass` (sorted back-to-front; water) | engine |
| Transparent (9) | `FirePass` | effects |
| Transparent (10) | `ParticlePass` | effects |
| Transparent (50) | `VolumetricFogPass` (half-res raymarch → upsample+blend), placed after transparents so water/particles are fogged | effects |
| PostProcess (-10) | `DepthOfFieldPass` *(opt-in)*: half-res prep → gather → blend by CoC | effects |
| PostProcess | `BloomPass` | effects |
| Composite | `CompositePass` (exposure + ACES tonemap + grading → Backbuffer) | engine |
| Overlay | `UiPass` (ImGui) | engine |

Passes may transition textures mid-pass with `graph.transition(cmd, id, access)`
(e.g. AtmospherePass renders the LUT then samples it), and the graph keeps
tracking the state.

**GPU profiling:** the graph writes a timestamp pair around every pass. The
renderer reads them back once that frame slot's fence has signalled, and smooths
them into `RenderPass::gpuTimeMs`, which is shown per pass in the F1 overlay.

### 5.5 Per-frame renderer flow

`Renderer::render()` reads as acquire → prepare → record → submit. The work
is done by parts the Renderer owns: `SceneGatherer` (scene → `FrameData`:
camera, draw items, culling and sorting, previous world matrices, lights; the
only render code that reads scene components), `ShadowSetup` (cascades and
cube faces), `LightClusterer` (CPU light binning) and `FrameCapture` (photo
mode, `VE_CAPTURE*`, readback and PNG). The Renderer keeps the frame loop,
the pipeline / shader / material registries and the shared GPU objects.
The command buffer starts with `Device::flushUploads` (queued buffer
uploads), and only dirty material slots are copied (D25).

1. Find the main camera and build view/projection (reversed-Z, Vulkan Y-flip).
2. Apply the scene's queued static changes to the `StaticBatcher` (D28); gather
   the other `MeshRenderer`s → draw items (world matrix, world AABB, submesh,
   material). Frustum-cull for the main view. Split into opaque (sorted by
   pipeline, then front-to-back) and transparent (back-to-front) queues.
3. Gather lights. Assign directional shadow slots (up to
   `settings.maxShadowedDirectionalLights`, each with `settings.cascadeCount`
   cascades) and point shadow slots (closest `settings.maxShadowedPointLights`
   within range). Compute cascade splits (practical split scheme) and
   texel-snapped, sphere-fitted orthographic matrices. Optionally
   (`settings.shadowDirectionStep` > 0, off by default) the light direction
   for shadows is snapped to steps of that many degrees: a moving sun
   re-rasterises every shadow edge from a new angle each frame, so the edges
   crawl (2–4 % of the ground's pixels change per frame with a still camera,
   TAA off; ~0.02 % snapped), but the steps themselves are visible. Lighting
   uses the exact direction. Compute the six cube-face matrices.
4. `pass->prepare()` for all enabled passes.
5. Upload FrameGlobals, LightBuffer and the dirty MaterialBuffer slots (host-visible, per frame in flight).
6. Acquire swapchain image, record graph (barriers + passes), submit, present.

### 5.6 Shadows

- Directional: a single `D32F` 2D-array texture with
  `maxShadowedDirectionalLights × cascadeCount` layers. Each layer is rendered
  as its own dynamic-rendering pass with per-cascade culling. Sampled with
  hardware PCF (comparison sampler) and a 3×3 kernel, normal-offset bias,
  slope-scaled raster depth bias, and depth clamp if supported.
- Point: a `D32F` cube-array with `maxShadowedPointLights × 6` layers. The
  fragment shader writes `distance / range` as depth, and lookups compare
  against the same value.
- Point faces are cached (`RendererSettings::cachePointShadows`, on by
  default): `ShadowPass` hashes each face's inputs (view, range, every
  caster's mesh, submesh, shader, world matrix and material data, plus
  `Renderer::contentEpoch()`, which bumps when shadow maps are recreated or
  shaders hot-reload) and skips faces whose hash matches their last render.
  A face with a deforming caster (a `SkinnedMeshRenderer`, `DrawItem::deforming`)
  is never cached: its vertices change while its mesh and matrix don't.
  Static torches and campfires re-render only when something in range moves.
  The shadow maps persist across frames, so a skipped face keeps its depth.
- Directional shadows sample a 3×3 PCF kernel as 4 bilinear taps with the
  same weights (exact for the default 1-texel radius; other radii fall back
  to 9 taps).
- Everything is configurable via `RendererSettings` (counts, cascade count,
  resolutions, split lambda, biases, max shadow distance).

### 5.7 GPU-driven instancing

For things there are thousands of (trees, rocks, bushes, later foliage) use
`InstanceGroup` instead of a GameObject + MeshRenderer each:

- `renderer.createInstanceGroup(desc, capacity)`: `desc` holds up to 4 LODs
  (mesh + materials + max distance), `castShadows`, `cullDistance` and
  `shadowDistance`. `add(transform, custom)` / `set` / `remove` use stable handles.
  `custom` is a free vec4 per instance; `standard.vert` uses `w > 0` to tint vertex colours.
- Storage: one device-local instance buffer (64 B per instance), sub-allocated
  per group. Only changed slot ranges are uploaded, through a per-frame staging buffer.
- Each frame `InstanceCullPass` dispatches `instance_cull.comp` per group, one
  thread per instance. The thread computes the bounding sphere and LOD (by
  camera distance) once, then tests every **cull view**: view 0 is the camera,
  then every directional shadow cascade (`ShadowView::cullView`). Per view it
  tests the distance limits, a minimum size (shadow views skip casters smaller
  than `shadowMinCasterTexels` cascade texels) and the frustum, and appends the
  instance to that LOD's batches with an atomic on the indirect command's
  `instanceCount`.
- **Occlusion** (camera view, `RendererSettings::occlusionCulling`, on):
  `HiZPass` (after the opaque geometry) reduces SceneDepth to a pyramid of
  512×256 … 1×1 R32F levels holding the farthest depth of their area. Next
  frame the cull projects each instance's bounding box with last frame's
  camera (`prevViewProj`), picks the level where it covers ≤ 2×2 texels and
  skips it if its nearest point is behind all four. Boxes reaching off
  screen or behind the camera always pass. Savanna: camera instance draws
  −55 % in the jungle, −59 % at the camp, identical images. Something coming
  out from behind cover can appear one frame late.
- **LOD:** each group has up to 4 `InstanceLod`s, selected per instance by
  screen size (`radius · cot(fov/2) / distance`, if `screenSize` is set) or
  distance, scaled by `RendererSettings::lodBias`. Shadow views use
  `shadowLodBias` coarser LODs. Near a threshold an instance is emitted into
  both LODs. The visible entry packs the instance index (23 bits), a fade value
  (8 bits) and an incoming/outgoing flag, and the fragment shader discards
  complementary 4×4 ordered-dither pixels (`veLodDither`) for a pop-free
  crossfade. LOD meshes come from `MeshData::simplified()` (meshoptimizer).
- **Impostors** (`render/Impostor.hpp`): `Impostor::bake(renderer, mesh, materials)`
  renders N×N hemi-octahedral views into albedo + normal atlases, and `impostor->lod()`
  is an `InstanceLod` (quad mesh + impostor material) used as the last level. The
  impostor shaders (`impostor.vert/frag`, `impostor_shadow.vert/frag`) share their math
  with the baker through `ve_impostor.glsl`. The bake projection has no Y flip, so
  its pipeline uses clockwise front faces (otherwise normals bake inverted).
- Draw batches are (group × LOD × submesh). Opaque and shadow passes call
  `instances().draw(ctx, cullView, kind, shadowViewIndex)`, which issues one
  `vkCmdDrawIndexedIndirect` per batch with `DrawPush::flags = INSTANCED`, from
  per-pass batch lists (forward / shadow casters) sorted by shader and mesh. In
  the vertex shader `veModelMatrix()` resolves
  `veInstances[veVisibleInstances[gl_InstanceIndex]]`.
- Limits: `RendererSettings::maxInstances`, `maxVisibleInstancesPerView`
  (cap on the sum of batch capacities), 1024 groups, 2048 batches, cull views
  for every possible cascade (`kMaxDirectionalLights × kMaxCascades`). The
  visible buffer holds active views × the sum of batch capacities and grows
  when groups are added. Point-light shadows and transparent materials don't
  draw instances (batched static renderers still reach point-light cube faces:
  the ones in a shadowed light's range are added as draw items, D28).
- **Static renderers** (`MeshRenderer::isStatic`, `GameObject::setStatic`, D28).
  The Renderer's `StaticBatcher` keeps every eligible static renderer (active,
  visible, opaque or cutout, not skinned) as an instance in a group per
  (mesh, materials, castShadows); groups double when full. The Scene queues
  changes (start, `refresh()`, transform dirtying of objects with batched
  renderers, `setActive`, reparenting, destroy, removal), so nothing walks the
  statics per frame. A 16 m grid of their bounds feeds point-light cube faces
  and editor picking. `RendererSettings::staticBatching` (F1) turns it off.
  Savanna: 3,000 building pieces went from ~16 ms main thread and ~10k draws
  to ~10 ms and ~1k draws (lavapipe, Release), with identical images.
- Stats (visible camera/shadow instance draws) are read back from the GPU one
  frame-slot later and shown in the F1 overlay.
- Cutout materials (`StandardMaterial::Mode::Cutout`) use `shadow_cutout.frag` /
  `shadow_point_cutout.frag` (`ShaderDesc::shadowFragment`), so shadows keep the
  alpha holes.

Shader stages: CMake defines `VE_VERTEX_STAGE` / `VE_FRAGMENT_STAGE` /
`VE_COMPUTE_STAGE` per file, so shared includes can expose stage-specific
helpers (the instancing helpers are vertex-only).

### 5.7b Skeletal animation and GPU skinning (`ve/anim`, `render/Skinning`)

- **Import.** The glTF loader reads skins (joint nodes + inverse bind
  matrices), `JOINTS_0` / `WEIGHTS_0` (a `SkinnedMeshSource` per skinned mesh:
  rest vertices, 4 joints + weights per vertex, and per joint the reach of its
  vertices for bounds) and animation clips (translation / rotation / scale
  channels; step, linear and cubic-spline keys).
- **Skeleton = objects.** `Scene::instantiate` makes every glTF node a
  GameObject as before, so joints are objects: attach a spear to a hand by
  parenting it. Skinned mesh nodes get a `SkinnedMeshRenderer` (a
  `MeshRenderer`) bound to the joint objects; animated models get an
  `Animator` on their root.
- **Animator.** Plays clips with crossfades: every playing clip has a weight
  that fades in or out; per animated node the clips' poses (rest pose for
  channels a clip doesn't animate) are blended (translation / scale
  weighted, rotations normalised-weighted in one hemisphere) and written to
  the node objects' local transforms. `play(name, fade, loop, speed)`.
- **Layers.** Layer 0 is the whole body; `addLayer(name, maskJoint, blend)`
  adds one over part of the skeleton (a joint and everything below it) that
  plays its own clips: Override replaces the pose under it, Additive adds the
  clip's difference from the rest pose. Each layer has a weight that fades
  (`setLayerWeight(layer, w, fade)`): e.g. wave / swing an axe with the arms
  while the legs walk.
- **Events.** `addEvent(clip, time, name)` + `onEvent(event, clip)`: fired when
  the current clip of a layer passes the time (loops included), not while it
  fades out. Footsteps, hit frames, sounds.
- **IK.** `TwoBoneIK` (upper / middle / end joint names, world `target`,
  `pole` in model space, `weight`) runs after the animation: the middle
  joint goes where the triangle's sides put it in the target / pole plane,
  then the upper bone turns onto it and the lower onto the target (exact;
  the end joint keeps its animated orientation). Joints no clip animates are
  reset to rest first so IK doesn't accumulate. `FootIK` puts two of them on
  the legs: raycasts under each animated foot, lifts / drops the foot onto
  the ground (relative to the model's ground plane, so walking keeps its
  lift), lowers the hips for the lower foot, smoothed.
- **GPU skinning.** `SkinningSystem` keeps four shared storage buffers (set
  0, bindings 10–13): rest vertices and weights (once per source, refcounted),
  this frame's joint matrices (per frame slot) and the skinned output, which
  is also a vertex buffer. Each frame the renderer asks every active
  `SkinnedMeshRenderer` for its joint matrices (in its own space:
  `inverse(meshWorld) · jointWorld · inverseBind`) and bounds (joint
  positions padded by their reach); `SkinningPass` (first pass of the frame)
  runs `skin.comp` once per mesh. The output range is a `Mesh::createShared`
  mesh (vertex buffer bound at an offset), so the colour, shadow, picking and
  motion-vector pipelines draw skinned meshes unchanged.
  Limits: `RendererSettings::maxSkinnedVertices` (262 144),
  `maxSkinJoints` per frame (8 192).
- **Aim IK.** `AimIK` turns a chain of joints (root first, with weights) so
  an axis of an effector joint points at a target: each joint takes its share
  of the remaining turn (the last finishes it), the aim is limited to
  `maxAngle` from the animated direction, a couple of iterations handle aims
  that start off the joints (eyes, a muzzle), and it blends in / out over
  `blendTime` when a target is set / cleared. `LookAtIK` is the preset for
  heads (Spine 0.15, Chest 0.25, Head 0.6, the face's +Z from the eyes).
- Not yet: motion vectors from skinning (moving bones of a standing
  character), root motion, full-body IK.

### 5.8 GPU layer (gfx)

- `Device`: instance, debug messenger, surface, physical-device selection
  (requires Vulkan 1.3 dynamic rendering + synchronization2 + descriptor
  indexing features), logical device, graphics queue, VMA allocator, an
  **asynchronous buffer uploads** (`uploadBuffers` copies the data into a
  per-frame staging ring and queues the copy; `flushUploads` records the
  queued copies at the start of the next frame's command buffer, between a
  write-after-read barrier and a transfer → read barrier, and
  `immediateSubmit` flushes them first, so bakes see their meshes;
  `uploadBuffersNow` blocks; staging blocks are reused after the same
  `kFramesInFlight` rule as deferred deletion), an immediate-submit helper, a
  **deferred deletion queue** that destroys GPU objects after
  `kFramesInFlight` frames, and a `VkPipelineCache` saved to
  `pipeline_cache.bin` next to the executable (checked against the GPU's
  vendor / device / UUID on load), so pipelines compile fast after the first run.
- `Swapchain`: as in tinyvulkan (FIFO, per-image present semaphores).
- `Buffer`/`Image`: VMA-backed, created from small desc structs.
- `Bindless`: allocates/frees slots in the texture and storage-image arrays (deferred free).
- `PipelineBuilder`: fluent builder (from tinyvulkan) extended with depth,
  multiple attachments, blending presets, depth bias and custom vertex input.

### 5.9 World: terrain, foliage streaming and GPU grass (`ve/world`)

**`Terrain`** (a GameObject; shape in `TerrainShape`, colours in
`TerrainLook`, stamps are `TerrainStamp` components) streams everything:
- **Data.** `data()` returns an immutable `TerrainData`: the generator inputs
  (a copy of the shape, biomes and stamps) plus a thread-safe LRU cache of
  64-cell sample tiles (heights + biome weights). Tiles are generated on
  demand by whoever queries (main thread, foliage worker, grass bake, mesh
  worker); a per-thread memo of recent tiles keeps lookups lock-free. Memory
  follows what is queried (`tileCacheMB`), not the world size. Edits produce a
  new snapshot (`version()` bumps); holders of the old one keep it alive.
- **Rendering.** `TerrainLod` walks a quadtree of 33×33-vertex nodes (level L
  samples every 2^L-th grid point). A node splits while the camera is within
  `lodFactor` × its size *and* all four children have meshes, so a coarser
  level always covers the ground. Vertices carry their parent-grid height and
  normal (`tangent`), and `ve_terrain.glsl` morphs them with camera distance,
  reaching the parent shape exactly where a node hands over: no popping.
  Skirts hide the cracks between levels. Meshes are built as jobs on the engine pool
  (tiles for the finest levels, the pure generator for coarse ones), uploaded
  under a per-frame budget, cached LRU, and drawn through pooled
  MeshRenderers on one hidden child, so culling, picking and every shadow pass
  just work (`terrain_shadow.vert` morphs too).
- **Ground materials.** Biomes (and rock) may have a `TerrainMaterial`
  (albedo / normal / roughness / AO, size, tint). Each node picks the three
  splat layers that weigh most in it: their indices go in `color.a`, their
  weights in `uv` and `tangent.w` (the parent normal is stored as x/z). A
  small float texture holds each layer's texture indices and scale;
  `terrain.frag` blends the layers by weight and texture height, samples rock
  triplanar, and blends a rotated, larger second copy with distance against
  tiling. Leftover weight shows the biome vertex colour.
- **Edits.** `TerrainEdits` (editor brushes) add per-sample height offsets
  and painted biomes, sparse in 64-cell tiles, inside `generateHeight` /
  `generateBiomes`, so every consumer sees them. A rebuild after brush edits
  only (`changedOnlyIn`) keeps the old snapshot's cached tiles, LOD meshes and
  collider tiles outside the brushed area; foliage and grass refresh just
  that area.
- **Physics.** 64-cell heightfield tiles exist around the camera, every
  `CharacterController` and every dynamic `Rigidbody` (`colliderDistance`,
  25 % hysteresis). The render mesh, `height()` and the grass all split cells
  along Jolt's (i, j)–(i+1, j+1) diagonal, so the visible ground is the
  physical one.


**`FoliageSystem`** (a GameObject) scatters `InstanceGroup` instances using
`FoliageLayer` rules.
- **Placement is a pure function.** Each layer has a jittered grid of
  candidates, one per `spacing`² square, seeded from (layer seed, grid x, z). A FoliageType without a seed uses
  FNV-1a of its name, so placement is the same with every compiler / platform.
  A candidate is kept if it passes, cheapest first: probability, world bounds,
  exclusion circles, value-noise clustering, height/slope range, the
  `density(FoliageSample)` callback, and `avoid` rules. An avoid rule
  re-evaluates the earlier layer's candidates in the neighbourhood, with a
  distance pre-check, so cross-layer spacing stays deterministic. As a result
  no placement data is stored, and `query(layer, p, r)` answers "what grows
  here" even for unloaded cells.
- **Streaming.** The world is split into `cellSize` cells (64 m). Each
  (cell, layer) pair within the layer's `viewDistance` is generated
  nearest-first by jobs on the engine pool (the system keeps its own
  distance-sorted queue, drained by up to `jobs::workerCount()` jobs). The main thread adds results to the
  layer's groups (one per variant) under `instancesPerFrame`, and unloads
  pairs beyond `viewDistance × unloadMargin`. Stale results are dropped by
  ticket. Static colliders are created (`bodiesPerFrame`) only for cells
  within `colliderDistance` of `colliderFocus`, and destroyed with 25 %
  hysteresis. `preload(pos)` loads the start area synchronously. Cell scans
  are clamped to the world bounds, so a 3 km view distance on a small map
  costs nothing.

**Interactive foliage.** Instances have stable ids (`FoliageInstanceId`: layer
+ placement grid square). `setState(id, s)` switches one to an alternative
look (`FoliageLayer::states`: meshes + colliders; `kFoliageRemoved` = nothing).
The system keeps these overrides (main thread only, so the worker needs no
lock) and re-applies them whenever a cell streams in; `overrides()` exports
them for save games. Each extra state gets its own InstanceGroups, created on
first use. Within `promoteDistance` of the collider focus, instances are
hidden and replaced by GameObjects (`promote`, plus a `FoliageLink` and,
unless provided, the instance's mesh and collider), and restored beyond
125 % of that distance or when the object is destroyed.

**`GrassPass`** (a RenderPass, Opaque stage, order 10; one pass per grass layer)
stores nothing per blade.
- **Setup.** The game's `height`/`mask` functions are sampled once into an
  R32F height texture (exact samples; manual bilinear via `texelFetch`) and an
  RGBA8 mask (density, colour mix, height scale, free).
- **Per frame.** The CPU walks 16 m tiles within `radius` and frustum-culls
  them using per-tile ground height ranges. It issues one instanced draw of a
  small clump mesh per tile, with instance count = clumps × the tile's best
  distance density.
- **Vertex shader.** `ve_grass.glsl` maps `gl_InstanceIndex` to an R2
  low-discrepancy point in the tile. A clump is kept if
  `index / count < mask.density × distanceFalloff`, so any prefix of the
  sequence is evenly spread and thinning never flickers. Far blades widen to
  keep coverage. Hidden clumps are moved outside the depth range.
- **Wind and output.** Wind comes from `frame.globalParams[windSlot]`. Blades
  write the thin G-buffer.
- **Benders.** `GrassBender` components (the Savanna player has one) push
  grass aside: each frame the 8 nearest the camera go to
  `frame.grassBenders` (position of the feet, radius), and `veGrassPlace`
  rotates every blade within the radius about its root, away from the
  bender, by up to ~70° near the centre (shadows bend the same way).
- **Shadows.** `GrassPass` is a `ShadowCaster` (a `Renderer::addShadowCaster`
  hook that `ShadowPass` calls for each directional cascade). It draws tiles
  within `shadowDistance` into cascades with texels ≤ `shadowMaxTexel`, using
  `grass_shadow.vert`. That shader shares placement and wind with the colour
  pass (`veGrassPlace`), so shadows sway with the blades. Cards use the
  alpha-tested `grass_card_shadow.frag`. Cost: about 0.5 ms at 30 m on Iris Xe.
- **Variation.** Each clump has a random yaw, a random tilt around a horizontal
  axis (`maxTilt`) and a random width.
- **Card mode.** With `cardMesh` set, the mesh is scaled uniformly by the clump
  height. Vertex y is the sway weight and uv goes to `grass_card.frag`, which
  alpha-tests `cardTexture`.

## 5.10 Gameplay helpers (`ve/gameplay`, `ve/scene/SaveGame`, `ve/scene/Prefab`)

- **Save games.** `ve::Saveable` (`saveState` / `loadState`) on any object or
  component; `save::capture(scene)` = level objects moved by physics +
  level objects destroyed (the scene loader remembers the level's ids,
  `Scene::levelObjects`) + every Saveable's state keyed by persistent id or
  object name (+ component type); `save::apply` destroys, moves, then calls
  `loadState`. Slots are JSON files (tmp + rename). The game decides when
  to reload the level before applying (Savanna: behind the loading screen).
  Settings files (`save::readConfig` / `writeConfig`) live in
  `<save folder>/config/`, so they never appear in `save::slots()`.

- **Proxy sets** (`ve/gameplay/ProxySet.hpp`, D27). The generic form of
  foliage promotion, for stored (not procedural) things: a `ProxySet` holds
  entries (stable id, type, transform, a `uint32` state, a small JSON
  payload) drawn through one InstanceGroup chain per `ProxyType`. Within the
  type's `promoteDistance` of the focus (an `ObjectRef`, else the camera) an
  entry becomes a GameObject (factory, prefab, or a plain object with the
  first LOD) carrying a `ProxyLink`; on demotion its transform and Saveable
  state go back into the entry; if gameplay destroys it, the entry is
  removed. Budgeted per frame; a 16 m grid answers `query` / `nearest`. Level
  entries (added before `start()`) get sequential ids; save games store only
  the difference to them. Scene files keep entries in a hidden `entries`
  field. Not yet: painting entries in the editor, network replication.

- **Inventory** (`ve/gameplay/Inventory.hpp`). `ve::Inventory`: a fixed number
  of slots of `{item, count}` with stacking (per-item max stack from a
  callback, `kDefaultMaxStack` otherwise), add / remove / count / move-or-swap
  and JSON save / load. Item definitions, icons and the inventory screen are
  the game's (Savanna's `Inventory.*`).

- **Prefabs** (`ve/scene/Prefab.hpp`). A `.prefab` file is JSON holding an
  object (type, fields, persistent components, children) at the origin.
  `prefab::instantiate` creates an instance: children's ids are derived from
  the root's, so a save game recreates them with the same ids. It also adds a
  `PrefabInstance` component pointing back at the file. Instances are copies:
  editing the file doesn't update them (no overrides / propagation yet).
  Save games record runtime-spawned instances (a `PrefabInstance` root that
  isn't a level object) under "spawned" and recreate them before restoring
  Saveable state.

- **Placement** (`ve/gameplay/Placement.hpp`), the mechanics of building:
  - `SnapPoint` components are typed points on a piece. `findSnap` keeps the
    piece's rotation and moves it so one of its points lands on a scene
    point. A pair counts as close if the piece's point would land within a
    radius of the target with its origin at the aim, or if the aim itself is
    within the radius of the target.
  - With `alignRotation` (fittings), the piece also turns about Y so its
    `facing` matches the target's, whichever way round is nearer the
    player's rotation. `SnapResult` gives the rotation and the target, i.e.
    the host piece.
  - `snapToGrid` / `snapAngle` are the grid helpers.
  - `fits` tests the piece's volume against physics: its `PlacementBox`es,
    or the bounds of what it draws if it has none, shrunk by a margin so
    neighbours that only touch are fine. A predicate can allow some hits,
    e.g. the terrain.
  - `PlacementPreview` is the ghost: a prefab instance with a
    `PlacementGhost` marker, its world-acting components disabled, not
    saved, and drawn with one transparent material tinted valid / invalid.
  - The game owns the pieces, rules, costs and the build tool; the editor
    uses the same snapping when dragging.

- **Interaction.** `Interactable` (component: prompt / `promptFn`, `onUse`,
  `onFocus`, reach, focus offset; or override `currentPrompt` / `use` /
  `focusChanged`) and `Interactor` (component on whoever interacts: each
  frame the focus = the eye ray's hit object or a parent with an
  Interactable, else the best Interactable in a view cone with a clear line
  of sight; `interact()` on its Input action; `prompt()` for the game's
  HUD). Mechanism only: Savanna decides what chopping, picking and
  collecting do and how prompts look.

## 5.11 Navigation (`ve/nav`)

Backed by **Recast & Detour** (linked `PRIVATE`, only included by
`Navigation.cpp`).

- **`NavMeshSurface`** (component): a tiled navmesh over a box around its
  object (or, with `streamRadius`, the tiles around the camera / a focus
  object over the whole terrain). Each tile's input is gathered on the main
  thread: terrain heights sampled directly (deep water marked unwalkable),
  static `Rigidbody` colliders (`Collider::triangles`, Jolt's shape
  triangulation; the terrain's own heightfield bodies are skipped) and
  foliage colliders (`FoliageSystem::forEachCollider`, deterministic, so
  unloaded cells count too). Tiles are voxelized and turned into Detour tiles
  as jobs on the engine pool and swapped in on the main thread; while a loading screen
  is up the surface registers a "Finding paths" load task that drives the
  build. `FoliageSystem` state listeners rebuild the tiles around a chopped
  tree; `rebuild(area)` is there for other changes. Queries: `findPath`
  (corners), `nearestPoint`, `randomPointNear`, `raycast`.
- **`NavAgent`** (component): joins the surface's `dtCrowd` once there is
  navmesh under it, then walks to `setDestination` targets with path
  following, steering and avoidance of other agents; writes its Transform in
  `lateUpdate` (turning towards where it walks), `arrived()` /
  `remainingDistance()` for the game's AI.
- Behaviour is game code: Savanna's `Villager` idles, wanders to random
  reachable spots and follows the player when asked ("walk with me").
- `showDebug` draws the navmesh's polygons near the camera as `ve::debug`
  lines (the same as the "Navmesh" debug channel; nav has no editor dependency).

## 5.11b Debug drawing (`ve/debug/Debug.hpp`)

`ve::debug::line / ray / arrow / path / cross / axes / box / aabb / circle /
sphere / capsule / cylinder / text` from anywhere (game code, components,
engine systems), sRGB colours, `{duration, thickness, depthTest}`. Lines are
collected per frame (or kept for `duration` seconds) and drawn by
`DebugLinePass` on the finished image (Overlay stage: after tonemapping and
TAA, under the UI, not in photos): one instance per segment expanded to a
screen-space quad (any thickness, clipped at the near plane), depth-tested
against SceneDepth with the hidden parts drawn at 25 %. Labels go to ImGui's
background list. Channels (`enabled("Name")` registers one, off;
`setChannel`) are switched in F1 > Debug draw; engine channels draw physics
bodies, terrain colliders, characters, the navmesh and nav agents (path
corners, destination, velocity).

## 5.12 Networking (`ve/net`)

Host-authoritative co-op (decision D19). `engine.net()` (or `net()` in any
GameObject / Component) is the session: offline by default, `host(port)` or
`join(address, port)`.

- **Frame:** `Network::poll()` at the start of the frame (also during loading,
  to keep connections alive; messages wait until the load is done), then the
  usual update / late update, then `Network::flush()` sends what this
  machine owns that moved (NetworkTransform) or changed (dirty
  NetReplicated).
- **Authority:** `isServer()` is true offline and on the host. Clients
  change the world only by asking: `toServer("name", payload)` runs the
  handler on the host (immediately, locally, when offline or hosting). The
  host applies it and replicates the result: `spawn(prefab, pos, rot,
  owner)` / `despawn(obj)` on every machine, `toClients(...)` for events.
- **Objects:** `NetworkObject` = identity (the GameObject id: level objects
  match because everyone loads the same level, spawned ones are created with
  the host's id) + owner (a peer, the host by default). `NetworkTransform`:
  the owner sends, others interpolate. `NetReplicated`: netWrite / netRead
  of custom state, sent when `markDirty()` is called; the host relays
  client-owned state to the others after checking the sender owns it.
- **Joining:** hello (game id + protocol version) -> welcome with the world
  snapshot (`worldSnapshot` hook; default `save::capture`), then spawns not
  in saves, owners, state and transforms. The client applies the snapshot
  in `onJoined` (default `save::apply`), possibly after rebuilding the level
  (messages wait while loading).
- **Messages:** one byte type + payload (`ve/net/Stream.hpp`); spawns, state,
  requests reliable and ordered; transforms unreliable. The transport
  (`ve/net/Transport.hpp`, ENet) is internal to the engine.

## 6. Physics

Backed by **Jolt Physics**. Jolt is linked `PRIVATE` and only included by
`ve/physics/*.cpp`, which share its types through the internal
`ve/physics/JoltInternal.hpp` (never included by a header or another
module; `tools/check_layering.py` enforces it), so engine headers and games
never see Jolt types. The module is split by concern: `PhysicsWorld.cpp`
(world, step, contacts, layers), `Collider.cpp`, `Rigidbody.cpp`,
`CharacterController.cpp`, `Joints.cpp`, `PhysicsQueries.cpp`,
`PhysicsDebug.cpp`, `PhysicsReflection.cpp`.

- **`Collider`** is an immutable, shared shape handle: `box`, `sphere`,
  `capsule`, `cylinder`, `convexHull(points|MeshData)`, `mesh(MeshData)`
  (static only), `heightfield(...)`, and `.offset(t, r)`. Build once and share
  (all crates use one box). The GameObject's world scale is applied when the
  body is created (`ScaledShape`).
- **`Rigidbody`** (component), created in `start()` from the Transform:
  - **Static**: terrain, buildings, trees.
  - **Kinematic**: follows its Transform every step and pushes dynamic bodies.
  - **Dynamic**: simulated, written back to the Transform with interpolation.

  It has mass, friction, restitution and damping, continuous collision for
  projectiles, forces/impulses/velocity, `teleport()`, and `syncFromTransform()`
  for moved static bodies.
- **`CharacterController`** (component) wraps Jolt's `CharacterVirtual`: a capsule
  moved by queries. It slides along walls, handles max slope and step height,
  sticks to the floor going downhill, pushes dynamic bodies (`pushStrength`),
  and has an inner body so thrown objects hit it. Its position is the feet.
  Call `move(horizontalVelocity, dt)` from `fixedUpdate()`; gravity and
  `jump(speed)` are handled for you.
- **Kinds:** `NonMoving` (static), `Moving` (kinematic + dynamic), `Character`,
  `Sensor`. Static vs static never collide, and characters are only hit by
  moving bodies. Raycasts ignore characters unless asked.
- **Collision layers (the game's):** up to 32 named layers
  (`physics().addLayer("Debris")`, "Default" = 0 always exists) and a
  symmetric matrix (`setCollision(a, b, false)`). Bodies name theirs
  (`Rigidbody::layer`, `CharacterController::layer`, `createStaticBody(...,
  layer)`); a Jolt object layer is the kind in its low 2 bits and the game
  layer above, and the pair filter checks both. Queries take a mask
  (`QueryFilter::layers`, `layerMask({"Debris"})`); characters walk into what
  their layer collides with.
- **Physics materials:** friction / restitution per body, plus a `surface`
  name ("Wood", "Stone"...): `Rigidbody::surface`, `FoliageType::colliderSurface`,
  `createStaticBody(..., surface)`; terrain tiles are "Terrain" (games look
  up the biome). Hits (`RaycastHit::surface / layer`), contacts
  (`Collision::otherSurface / otherLayer`) and characters
  (`CharacterController::groundSurface / groundObject`) report it: footsteps,
  impact sounds and effects.
- **Joints** (components next to a Rigidbody, on Jolt constraints): `FixedJoint`
  (weld), `HingeJoint` (doors, wheels, pendulums: axis, limits in degrees,
  friction), `SliderJoint` (axis, limits in metres), `DistanceJoint` (ropes /
  springs between two anchors). The other body is `connect(object)` or
  `connectedTo` (a name, for scene files); none = the world. Hinges and
  sliders take a motor (Velocity or Position, max force, stiffness), limits
  can be soft (spring frequency / damping). `breakForce` / `breakTorque`:
  the solver's impulses each step / dt are compared and the joint comes off
  (`onBreak`, `broken()` saved in games). A joint attaches once both bodies
  exist and detaches before either is destroyed (a rebuilt body gets it back).
  F1 > Debug draw > "Physics joints".
- **Queries:** `physics().raycast(origin, dir, maxDist, ignoreBody, hitCharacters)` →
  point, normal, distance, `Rigidbody*`, `GameObject*` (via body user data),
  layer, surface; casts and overlaps take a `QueryFilter`.
- **Debug drawing:** `drawDebug(center, radius, ...)` draws body wireframes as
  `ve::debug` lines (F1 > Debug draw > "Physics colliders" / "Physics terrain" /
  "Character controllers").
- `scene.instantiate(model, parent, /*staticColliders*/ true)` gives every glTF
  mesh node a static triangle-mesh collider. `Model` keeps CPU `meshData` for this.
- Threads: Jolt's job system with up to 4 workers. Per-step CPU time is shown in the F1 overlay.

## 7. Assets

- `AssetManager` resolves paths against search roots (`<exe>/assets`, plus any
  added), caches by path, and returns `shared_ptr`s.
- Textures: stb_image (PNG/JPG/TGA/BMP/HDR), sRGB or linear, mip chains made with
  blits, and auto-registered in the bindless table. `Texture::fromPixels()` and
  `Texture::create3D()` cover procedural data (e.g. cloud noise).
- Models: glTF 2.0 (`.gltf`/`.glb`) via cgltf. Meshes and primitives become
  `Mesh` + submeshes. Materials become `StandardMaterial` (base colour /
  normal / metallic-roughness / emissive textures and factors), and the node
  hierarchy becomes `Model`.
  `scene.instantiate(model)` spawns a GameObject hierarchy with MeshRenderers.
- Audio: `AudioClip` = path + decode mode, played through miniaudio's resource manager.

## 8. Audio

`AudioSystem` wraps `ma_engine`. `AudioSource` (component) owns an `ma_sound`, follows
its transform (3D spatialization with min/max distance), and can loop and
play on start. `audio.playOneShot(clip, volume, position?, pitch, bus)` fires and forgets.
The listener follows the main camera.

- **Buses:** each `AudioBus` is a miniaudio sound group feeding a 2nd-order
  low-pass node, which feeds the output. The built-in buses are SFX, Ambient,
  Weather, Music and UI; `bus(name)` creates more. Every sound plays through
  `AudioSource::bus`. `volume`/`lowpass` are the game's settings (options menu),
  and zones apply on top. Cutoffs interpolate in log-frequency, and the filter
  is only re-initialised when the cutoff changes by more than 1 %.
- **`AudioZone`** (component; box, sphere or vertical cylinder in local space)
  registers with the system. Each frame `AudioSystem::update` marks zones that
  hold the listener, takes the strongest effect per bus (min volume, min
  cutoff) and approaches it exponentially over `fadeTime`. Typical use is
  "indoors": the Weather bus at 0.3× and 450 Hz.
- **Occlusion** (`AudioSource::occlusion`, 3D only): the source gets its own
  low-pass node (sound → filter → bus). Every ~0.13 s (staggered) it casts 3
  physics rays from the listener to the source and two points beside it,
  stopping 0.6 m short and ignoring the source's own Rigidbody and characters.
  The blocked fraction is smoothed and drives volume (`occlusionVolume`) and
  cutoff (`occlusionLowpass`). Terrain heightfields, building mesh colliders
  and streamed foliage colliders all occlude.
- The F1 overlay has an Audio section with bus volumes, current zone
  volume/cutoff, and the zone count.

## 9. UI

Dear ImGui with the SDL2 and Vulkan (dynamic rendering) backends. It is drawn
by `UiPass` directly onto the backbuffer. Games draw HUD/menus in `onGui()`
hooks (debug tools, the editor); game screens use the retained layer
below. F1 toggles the engine debug overlay: FPS/frame time, draw counts,
CPU zones (`VE_PROFILE` scopes from `ve/core/Profiler.hpp`, main thread,
nested, averaged over ~1 s), renderer settings (shadows, exposure), and every
render pass with an enable toggle, its GPU time and its own `onGui()` settings.

### 9.1 Game UI (`ve/ui/Gui.hpp`)

A small retained-mode layer for game screens (HUD, inventory, menus), drawn
through ImGui's background draw list (so it shares fonts, textures and the
`UiPass`) but not using ImGui widgets. The engine holds the mechanism; the
look (colours, fonts, layouts) and what screens exist are the game's.

- `ui::Canvas` (a Component): a tree of `ui::Element`s laid out on a
  reference resolution (1920x1080, scaled by window height). `order` sorts
  canvases; a `modal` canvas takes all input (the game stops seeing keys and
  the mouse) and owns keyboard / pad focus. `onBack` (Escape / pad B),
  `shortcuts` (key or pad button -> action), `fade`, `hideInEditor`.
- Elements: anchors + pivot + position + size (stretched between two
  anchors, the position / size are insets), `visible`, `enabled`,
  `opacity`, `tooltip`, `onClick`, `onHover`, drag and drop (`draggable`,
  `onDrop`, `dragVisual`). Widgets: `Panel` (fill / gradient / border /
  image), `Label` (font + size, alignment, wrap, shadow, `bind` for live
  text), `Image` (texture or a `custom` draw callback), `Button`,
  `ProgressBar` (gradient fill, trail), `Slider`, `Stack` (vertical /
  horizontal), `Grid`.
- Input routing (`ui::System::route`, before gameplay each frame): hover,
  press, click, drag, tooltips; focus navigation on the top modal canvas
  with arrows / d-pad / left stick, Enter / Space / pad A to click. It sets
  `Input::setUiCapture`, so gameplay's keys, mouse and pad go quiet under a
  modal canvas.
- `ui::Painter` draws in canvas units (rects, gradients, borders, lines,
  polygons, circles, images, text); colours are authored in sRGB and
  converted for the sRGB backbuffer.
- Fonts: `ui::loadFont(name, ttf, sizes)` bakes sizes into the atlas (any
  time: applied before the next frame); text picks the nearest baked size
  and scales.
- Text fields: `ui::TextInput` (click or focus it and type: text from the
  OS via `Input::textTyped()`, so keyboard layouts and IMEs work; caret,
  Backspace / Delete / arrows / Home / End with key repeat, `accept` filter,
  `onChanged`, `onSubmit` on Enter, Escape stops editing). While a field is
  edited the keyboard belongs to it: gameplay keys, the canvas's shortcuts,
  Space-to-click and Escape-to-back are off. Tests: `Input::injectText` /
  `injectKeyTyped`.
- Lists: `ui::ScrollView` clips its `content()` (a vertical Stack), scrolls
  with the wheel, its bar or by dragging, and follows keyboard / pad focus
  (`scrollTo`). Hit-testing skips what's clipped (`Element::clipsChildren`).
- Icons: `ui::bakeIcon(renderer, meshData, size, view)` renders a mesh
  offscreen (orthographic, three-quarter view, simple lighting) into a
  texture for inventory / build menu slots. Textures kept outside the
  scene (a static item table) must be dropped in `Engine::atShutdown`,
  which runs before the renderer is destroyed.

Input (`ve/core/Input.hpp`) maps keys, mouse buttons, gamepad buttons and
triggers to named actions, and keys or stick axes to named axes; the first
SDL game controller is used. Bindings can be rebound at runtime
(`startRebind`) and saved as JSON; the game decides where and draws the UI.

## 10. Effects module (ve_effects, namespace `vfx`)

Optional add-ons built only on public engine APIs:

- `AtmospherePass`: analytic single-scattering sky (Rayleigh + Mie, tuned for
  warm sunsets), a sun disk, and volumetric clouds raymarched through a slab
  using a CPU-generated 3D Perlin-Worley noise texture. It also sets the
  hemispherical ambient light in frame globals from the sun elevation. The ground
  term reports its sunlit-bounce share (`Environment::groundSunFraction`, i.e.
  `ambientGround.w`), and `veAmbient` scales that share by the sun shadow 2 m
  out from the surface. Objects therefore stop glowing orange once the sun is
  behind terrain.
- `VolumetricFogPass`: a half-resolution raymarch from the camera to scene depth
  into `FogBuffer`. It uses exponential height fog, 3D noise, a Henyey-Greenstein
  phase function, shadow-cascade sampling for god rays, and only the point lights
  whose sphere the ray actually crosses. Ambient light is the sky averaged over
  the hemisphere (not the view direction, so fog doesn't glow toward a hidden
  sunset). Beyond the last cascade, sun visibility is the average seen in the
  last cascade along that ray. A 4×4 ordered (Bayer) jitter is used,
  and a matching 4-tap box upsample blends the result over SceneColor.
- `BloomPass`: threshold + progressive downsample/upsample chain added back into SceneColor.
- **Screen-space passes (opt-in; not added by `addDefaultEffects`).** They read
  the thin G-buffer `SceneNormal` (§5.4). SSGI and SSR share
  `ScreenSpaceTracePass` (trace at reduced resolution → `TemporalAccumulator`
  → upsample-and-blend over SceneColor); each only supplies its shaders and
  push constants:
  - `ScreenSpaceGIPass`: 3 cosine rays × 8 steps per half-res pixel, marched
    through SceneDepth. Hits gather the lit SceneColor (one diffuse bounce,
    luminance-clamped against fireflies) and count as occlusion. The ray
    rotation is a 4×4 Bayer pattern offset every frame, and a
    `TemporalAccumulator` blends about 10 frames. `ssgi_apply.frag` then takes
    an exact, normal/depth-aware 4×4 average (4 bilinear taps on texel corners),
    which always holds all 16 rotations. The bounce is tinted by the receiver's
    own colour chroma, because there is no albedo buffer.
  - `TemporalAccumulator` (shared by SSGI and SSR): ping-ponged half-res
    history plus linear depth. It reprojects with `frame.prevViewProj`, rejects
    history on a depth mismatch or off-screen, clips it to the current 3×3
    mean ± 1.5σ, then blends. Without the accumulation, small bright emitters
    (sunstones, fire) showed as dot patterns.
  - `ScreenSpaceReflectionsPass`: a view-space ray march (quadratic step
    distribution with per-frame jitter, binary refinement, temporally
    accumulated) for surfaces below `maxRoughness`. It is
    weighted by Fresnel, edge/distance/roughness fades and back-face rejection.
    Transparent geometry and particles are not in SceneColor yet, so they are
    not reflected.
  - `DepthOfFieldPass`: thin-lens CoC = `aperture · |1/focus − 1/depth|`
    (outside a sharp `focusRange`), with auto focus from centre-screen depth.
    Half-res prep packs colour + linear depth; a golden-angle gather where
    background taps are clamped to the centre's CoC; full-res composite with
    alpha = CoC. Cost at 1600×900 on Iris Xe: SSGI about 1.3 ms, SSR about
    0.3 ms, DOF about 1.2 ms.
- `Fire` component and `FirePass`: procedural flames, no textures and no
  simulation. Each fire is 1–8 vertical sheets turned around Y towards the
  camera (each a little off-axis and offset, so they read as one volume),
  bent downwind at the tips, plus a horizontal coal bed. The fragment shader
  rises domain-warped value noise through a teardrop shape, tears the top
  into tongues and colours the "heat" with a black-body-like ramp. Output is
  additive HDR with soft depth fades, and bloom makes the glow. The
  component's `flicker()` / `lightJitter()` drive a point light so the glow
  and shadows follow the flames. Cost: about 8 noise lookups per pixel over a
  few small quads.
  - Heat haze (`Fire::haze`): after the flames, the pass copies only the
    screen rectangle the fires' haze boxes project to (`FireHazeCopy`), then
    draws one camera-facing sheet above each fire (`fire_haze.frag`). It
    samples the copy at offsets from rising noise, about 5 cm in the world
    (so it shrinks with distance). It is masked at the sheet's edges and
    never pulls in pixels from in front of the hot air. The flame tips are in
    the copy, so they shimmer too.
- `ParticleEmitter` component (CPU simulation) and `ParticlePass`
  (instanced camera-facing or velocity-stretched quads, alpha/additive).
  - Streaks stretch along the actual motion, wind drift included, so rain
    slants in the wind.
  - With `collide`, each particle casts one physics ray along its motion at
    spawn and dies at the hit height, so roofs, rocks and crates stop rain.
    The weather's rain enables this.
- `ColorGradingPass` *(opt-in)*: HDR → exposure (the composite's, so
  adaptation and lightning apply), white balance (LMS), colour filter, log
  contrast, saturation/vibrance, then one of 7 tonemappers (ACES fitted/Hill,
  AgX, Hable filmic, Reinhard, Khronos Neutral, none), then split toning,
  lift/gamma/gain and an optional strip LUT.
  - It writes `GradedColor` and calls `CompositePass::useGradedInput()` each
    frame, so the composite only adds vignette and dither. Disabling the pass
    restores the built-in tonemapping.
  - Presets: `neutral()`, `sunBleached()` (a starting point).
  - `tools/generate_assets.py` writes `lut_neutral_32.png` for authoring LUTs.
- `Weather`: a GameObject that blends presets (clear/hazy/overcast/rain/thunderstorm)
  by driving the atmosphere, fog, light intensity and a rain emitter that follows
  the camera.
  - Sound layers (`rainSound`, `stormSound`, `windSound`) are loops on the
    "Weather" bus. Their volumes come from the blended state (rain × (1 −
    thunder), thunder, wind), so a weather change crossfades them over the
    transition, and AudioZones muffle them indoors.
  - Thunderstorms add lightning as short multi-pulse `CompositePass::exposure`
    boosts at random intervals. These aren't synced to the thunder in the
    loop.
- Global shader param convention (`vfx::GlobalSlot`, `vfx.glsl`):
  `[0]` wind (xy dir, z strength, w gust), `[1]` weather (x wetness, y rain,
  z cloud coverage, w fog multiplier), `[2]` direction towards the sun + illuminance,
  `[3]` sun radiance after the atmosphere.
